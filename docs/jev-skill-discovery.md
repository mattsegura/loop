# Optional Jev skill discovery

Off by default. To permit external ranking, the server operator must explicitly set both `LOOP_JEV_SKILL_RERANK=1` and `LOOP_JEV_ALLOW_DISCOVERY_EGRESS=1` and supply `TYPESAFE_API_KEY`. These are process-wide settings, not per-user consent. Leave egress off in workspaces where queries or skill descriptions cannot leave the server.

After profile, category, enabled and agent ACL checks, ambiguous MCP skill results may send the query (at most 400 characters) and up to four authorized names/descriptions (96/256 characters) to api.typesafe.ai. No body, path, ID, profile, or history field is sent; the allowed text fields can themselves contain private information. One request, no retries, 2.5 second timeout. As in the [live reranking cookbook](https://docs.typesafe.ai/cookbooks/rerank_typesafe), Noul relevance judgments are comparable across candidates. The top score must reach .75 and lead the runner-up by .15. Failure or uncertainty retains the original list. This stage neither loads nor executes skills and cannot add candidates, change confidence, or turn a no-match into a match.

Reproduce with `node scripts/eval-jev-skills.mjs` (no network) or supply a credential and pass `--live` (hardcoded synthetic data only). The Nov 23, 2026 live run used MCP dispatch and hybrid lexical retrieval with no embeddings, five synthetic skills, and eight labeled cases. Baseline: 7/8, zero calls. Candidate: 8/8, three successful requests, six judgments. One correction: “file these away” chose the audio archive instead of the cleanup skill. Two judgments confirmed the existing top result; a clear match, exact ID/name, no-match, and denied-only cases used no requests. Small smoke test, not evidence of broad accuracy gains. Offline regressions: `node --test test/jev-skill-discovery.test.mjs`.
