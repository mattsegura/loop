# Access, sign-in handoffs, and scheduled reads

Discovery is a hint to the agent, not proof of the logged-in account. An exact tool inspection can include an adapter's safe `verificationArgs`. For a supported self-read, the caller can run `loop__run` with `verifyOnly: true` and those exact arguments. This follows normal access and approval checks. Only gateway-generated evidence for the current account, tool and session qualifies. A Gmail profile verifies mailbox identity and totals, not permission to search, send, or modify mail. A read without evidence must not be promoted to verified.

Loop Text's durable runtime can resume a Messages request after its sign-in wait expires. The user completes the linked connection in the dashboard. A pending handoff belongs to its original thread and link; continuation never grants additional access. An ordinary follow-up preserves the handoff. A status update or a claim that sign-in is done is not evidence of access. Explicit cancellation, replacement, or disconnection can end the handoff. Approval, execution and delivered reply remain distinct events.

Scheduled reminders send their text without running an agent. Scheduled app reads pin the verified account and exact arguments and recheck at dispatch. Independent execution requires positive hosted-route evidence. If a legacy app job has only a free-form prompt, it needs review rather than running with unrestricted tools. Device-bound mode requires explicit confirmation and an online, verifiable device route; ordinary browser sessions alone do not provide that proof.

Rollout: release the gateway and Messages service together. First verify in staging with a dedicated test account. Complete sign-in in the dashboard after the original wait, restart Messages, and confirm exactly one substantive reply in the original thread. Send a status follow-up during the wait and confirm it does not cancel the request. Before enabling a recurring read, check that an account switch or revoked access pauses the job and an offline computer or timeout retries, then confirm a supported hosted read works without the computer. Do not use a production mailbox to test delivery without permission.
